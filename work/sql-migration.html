Migrating 20 years of historical demographic data from a legacy system into a documented SQL Server database.

The Pennsylvania State Data Center kept two decades of demographic records in Microsoft Access, split across five research projects running at the same time. Each project had its own structure and almost no documentation, so answering a simple question meant knowing which file to open and what its columns used to mean.

I moved the records into SQL Server, designed a normalized schema for them, and documented it well enough that the next analyst wouldn’t have to reverse-engineer anything.

Designing the schema

Twenty years of ad hoc data entry leaves quirks: fields that changed meaning over time, exceptions typed in by hand. I designed normalized tables that could hold all of it without flattening those quirks away, then indexed them. Together, the new schema and indexes cut query and processing time by about 30%.

Checking nothing was lost

Every historical record carried over, and the analyses already built on the old data kept working.

Writing it down

A migration isn’t finished when the data lands; it’s finished when someone else can find things in it. I wrote schema dictionaries, metadata inventories and update logs for all five projects. Before, different analysts assumed different meanings for the same field, and their numbers disagreed. With one shared dictionary, those recurring discrepancies stopped.
