Twenty years of demographic data was sitting in Access - the migration to SQL Server was the whole project.

The Pennsylvania State Data Center (PaSDC) had two decades of legacy demographic records living in Access, spread across five concurrent research projects with no consistent schema or documentation between them. Before any dashboard or analysis could happen, that data needed a real home - normalized, indexed, and documented well enough that the next analyst wouldn't have to reverse-engineer it from scratch.

From Access to SQL Server

The migration itself was straightforward in theory and messy in practice - designing normalized schemas and table structures that could actually hold two decades of records without losing the quirks and exceptions baked into years of ad hoc data entry. Getting the structure right up front was what made everything after it possible.

Building the reference layer

A migration isn't finished when the data lands - it's finished when the next person can find anything in it. Schema dictionaries, metadata inventories, and update logs went in across all five concurrent projects, so retrieval stopped depending on institutional memory.

  • Migrated 20+ years of records with zero data loss

    Every historical record carried over, normalized and indexed, without breaking the analyses already built on top of it.

  • Cut query execution and processing time by 30%

    Indexing and schema redesign turned slow, ad hoc queries into something researchers could actually rely on.

  • Eliminated recurring data discrepancies

    Standardized schema dictionaries closed the gap between what different analysts assumed a field meant.
