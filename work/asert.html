A 25-year study needed a data pipeline it never had - and a statewide program needed a way to compare costs that don't naturally compare.

The prevention studies at the center span more than two decades, which meant the data was never designed to be analyzed together - different formats, different variable names for the same thing, different missing-data conventions depending on which year or cohort collected it. That was the first project. The second came later and looked nothing like the first on paper: leading the data side of a cost-benefit analysis for a statewide autism services initiative, which meant pulling financial data out of three separate organizations' systems and making it comparable at all.

A study older than the pipeline it needed

Building the pipeline meant designing research database schemas with field-level validation, branching logic, and relational constraints robust enough to handle multi-format ingestion across a 25+ year study - then applying systematic missing-data handling rules consistently across every instrument, instead of each one being patched by hand.

Three organizations, one cost model

This cost-benefit work started as a data problem before it was a statistics problem: three partner organizations track spending in three different systems, using different categories for what's effectively the same activity. Before any cost-benefit analysis could happen, someone had to define how a line item in one organization's system maps to a line item in another's - and make that mapping defensible enough that all three would trust the resulting comparison.

  • Cut report turnaround time 40%

    Automated validation checks across the center's behavioral health studies meant investigators stopped waiting on manual data cleaning before analysis could start.

  • Trusted with the cross-org financial work

    Asked to lead the ERP data integration for the statewide initiative - work that sits outside a typical data-management role, built on the pipeline work that came before it.

  • Built the literature-monitoring layer too

    AWS-hosted Streamlit dashboards with REST API integrations (Overton, OpenAlex) now track 10,000+ published articles for the team.
